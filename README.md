# PMAE: Tabular Data Imputation

An implementation and experimental study of **Proportionally Masked Autoencoders (PMAE)** for tabular data imputation, with **ReMasker** included as a comparative baseline.

This repository extends the original single-dataset workflow into a reusable **multi-dataset experimentation pipeline**. It brings dataset loading, preprocessing, artificial missing-value generation (amputation), model training, imputation, and evaluation together behind a common Python package and command-line interface.

> **Project title:** An Implementation of Proportionally Masked Autoencoders for Tabular Data Imputation

The project is an implementation and study of the published PMAE method. It is not presented as a new imputation architecture or as an exact reproduction of every experiment reported in the original paper. Results generated by this repository must be described together with their dataset, preprocessing, missingness, model, and evaluation configurations.

## Research reference

Jungkyu Kim, Kibok Lee, and Taeyoung Park. “To Predict or Not to Predict? Proportionally Masked Autoencoders for Tabular Data Imputation.” *Proceedings of the AAAI Conference on Artificial Intelligence*, vol. 39, no. 17, pp. 17886–17894, 2025.

- [Publisher paper](https://ojs.aaai.org/index.php/AAAI/article/view/33967)
- [DOI](https://doi.org/10.1609/aaai.v39i17.33967)
- [arXiv preprint](https://arxiv.org/abs/2412.19152)

The original paper introduces a proportional masking strategy that uses each feature's observed-value proportion when constructing the training mask. In this implementation, the per-feature masking ratio is computed from the observed proportion using the configured coefficients, clipped to a valid range, and fully observed features are handled separately. The PMAE model uses the MLP-Mixer-style block configuration retained from the implementation; ReMasker is included as a Transformer-based MAE baseline.

## Project workflow

The framework separates data preparation from model training:

```text
Original datasets
      |
      v
Dataset registry and loader
      |
      v
Preprocessing
  - remove identifiers and prediction targets from imputation inputs
  - identify numerical and categorical features
  - handle source-missing values
  - encode categorical columns
      |
      v
Processed complete feature matrix + metadata
      |
      v
Amputation (MCAR / MAR / MNAR)
      |
      v
Incomplete matrix + artificial missingness mask
      |
      +-------------------------+
      |                         |
      v                         v
    PMAE                    ReMasker
      |                         |
      v                         v
 Imputed data              Imputed data
      |                         |
      +------------+------------+
                   |
                   v
       Evaluation on artificially
             hidden cells
                   |
                   v
        Metrics, CSVs, histories,
        configurations, checkpoints
```

**Amputation is a data-preparation step, not the PMAE model.** It creates controlled missingness in an otherwise observed dataset so that imputation can be evaluated against retained ground-truth values. PMAE is the primary method implemented in this project; ReMasker is the comparison baseline.

### Dataset handling decisions

- **Online News Popularity:** `url` is treated as an identifier and `shares` as the prediction target; neither is used as an imputation feature.
- **Adult:** the official training and test files are combined for the unsupervised imputation experiment. `income` is excluded from the feature matrix. The source uses `?` for unknown values; the current reader identifies 6,465 pre-existing missing feature cells.
- **Default of Credit Card Clients:** `ID` and the default-payment outcome are excluded. Discrete fields such as `SEX`, `EDUCATION`, `MARRIAGE`, and repayment-status fields are configured as categorical.
- **Online Shoppers:** `Revenue` is excluded as the prediction target; configured discrete fields are treated as categorical.
- **Letter Recognition:** the letter label is excluded; the 16 input attributes are used.
- **Bike Sharing:** daily and hourly datasets are separate configurations. Rental-count outcomes and row/date identifiers are excluded.
- **Obesity Levels:** `NObeyesdad` is excluded as the prediction target; discrete/text attributes are treated as categorical.
- **Wine Quality:** red and white are separate configurations; `quality` is excluded as the target.
- **Diabetes:** predictors are loaded through `sklearn.datasets.load_diabetes`; the target is retained separately and excluded from the imputation matrix.

Identifiers and prediction targets are excluded from the imputation inputs to avoid using row identifiers or target information as predictors. Where available, target values are retained separately in the processed payload for reference.

### Pre-existing missing values

Adult contains source-missing feature cells represented by `?`. During preprocessing, numeric columns are filled with their median and categorical columns with their mode so that a finite reference matrix and stable category mappings can be stored. The original source-missing locations are separately recorded in a cell-level mask. When the incomplete model input is constructed, those locations remain missing. They are **not** included in the artificial evaluation mask because their true values are unknown.

The same rule applies to any future dataset with source-missing values: only values that were observed in the original source can be artificially hidden and scored against known ground truth.

### Categorical representation and limitation

The current PMAE and ReMasker implementations use a scalar-valued decoder. Categorical columns are therefore mapped to stable ordinal codes and placed after numerical columns in the model matrix. Predictions for categorical columns are rounded and clipped to the valid code range, then decoded to the original category labels for the human-readable CSV output.

This is a compatibility approach for mixed-type datasets, **not a native categorical embedding, categorical decoder, or categorical likelihood**. Ordinal codes impose an artificial ordering between categories, so categorical metrics—especially for high-cardinality features—must be interpreted cautiously. A categorical-aware architecture and loss function would be a separate model extension.

## Missingness generation (amputation)

The pipeline supports three artificial missingness mechanisms:

- **MCAR (Missing Completely At Random):** values are selected randomly within the chosen feature columns.
- **MAR (Missing At Random):** missingness weights depend on other observed feature columns that are not selected for masking.
- **MNAR (Missing Not At Random):** a self-masking mechanism makes missingness depend on the observed values of the feature being masked.

Two parameters control the generated missingness:

- `--column-fraction`: fraction of eligible feature columns selected for artificial missingness.
- `--missing-rate`: fraction of originally observed values to hide within each selected column.

The selected-column count is rounded up to an integer. Therefore, the realized overall fraction of missing cells can differ from the simple product of `column-fraction` and `missing-rate`, particularly for datasets with relatively few features. The actual missing fraction and selected columns are written to the amputation metadata.

For MAR, at least one eligible feature column must remain unselected so it can act as an observed driver. Do not use `--column-fraction 1.0` with MAR. The default value of `0.3` leaves possible driver columns for all bundled datasets.

The artificial mask follows the convention **`True` = artificially hidden cell**. Source-missing values are not included in this mask. Evaluation is performed only on cells marked by this artificial mask.

## Environment setup

The project metadata supports **Python 3.9 to 3.12**. Python 3.10 is a recommended environment for the pinned PyTorch 2.2.1 dependency. Avoid Python versions outside the declared range unless you independently verify that compatible PyTorch wheels are available.

```bash
conda create -n PMAE python=3.10 -y
conda activate PMAE
python -m pip install --upgrade pip
```

Install the dependencies pinned in `requirements.txt`:

```bash
python -m pip install -r requirements.txt
python -m pip install -e . --no-deps
```

```powershell
python -m pip install torch==2.2.1 --index-url https://download.pytorch.org/whl/cpu
```

## Command-line usage

Run all commands from the repository root.

### 1. List supported datasets

```bash
python run_experiment.py list-datasets
```

Available dataset keys:

```text
online_news
adult
credit_default
online_shoppers
letter_recognition
bike_daily
bike_hourly
obesity
wine_red
wine_white
diabetes
```

### 2. Prepare a dataset

Prepare one dataset:

```bash
python run_experiment.py prepare --dataset adult
```

Rebuild its processed files:

```bash
python run_experiment.py prepare --dataset adult --force
```

Prepare all registered datasets:

```bash
python run_experiment.py prepare-all
```

Generated files are stored under:

```text
data/processed/<dataset>/
├── processed.pkl
└── metadata.json
```

The processed payload contains the model-ready feature matrix, ordered feature names, numerical feature count, categorical feature names and mappings, fill values, target data (when present), source-missing mask, and source metadata. Numerical columns are ordered before categorical columns.

### 3. Generate an incomplete dataset

Example: generate MAR missingness for Adult using 30% of the columns and a 50% missing rate within each selected column:

```bash
python run_experiment.py amputate \
  --dataset adult \
  --mechanism MAR \
  --column-fraction 0.3 \
  --missing-rate 0.5 \
  --seed 42
```

The generated artifacts are saved under:

```text
data/amputated/<dataset>/<MCAR|MAR|MNAR>/
└── columns_<fraction>/rate_<missing-rate>/
    ├── seed_<seed>.npz
    └── seed_<seed>.json
```

The `.npz` file stores `X_incomplete` and the boolean artificial missingness `mask`. The companion JSON stores the selected columns, requested and realized missingness rates, mechanism, seed, and dataset metadata.

### 4. Run PMAE and ReMasker

Example: train both models on Adult with MAR missingness:

**Windows PowerShell**

```powershell
python run_experiment.py run `
  --dataset adult `
  --mechanism MAR `
  --column-fraction 0.3 `
  --missing-rate 0.5 `
  --seed 42 `
  --epochs 300 `
  --batch-size 128 `
  --device cpu `
  --models pmae,remasker
```

**Linux / macOS**

```bash
python run_experiment.py run \
  --dataset adult \
  --mechanism MAR \
  --column-fraction 0.3 \
  --missing-rate 0.5 \
  --seed 42 \
  --epochs 300 \
  --batch-size 128 \
  --device auto \
  --models pmae,remasker
```

Run only PMAE:

```bash
python run_experiment.py run --dataset wine_red --models pmae --epochs 300
```

Run only ReMasker:

```bash
python run_experiment.py run --dataset wine_red --models remasker --epochs 300
```

The main run command also accepts the following model configuration options:

| Argument | Default | Description |
|---|---:|---|
| `--embed-dim` | 32 | Model embedding dimension |
| `--depth` | 4 | Encoder depth |
| `--decoder-depth` | 2 | Decoder depth |
| `--num-heads` | 4 | Number of attention heads used by Transformer blocks |
| `--mlp-ratio` | 4.0 | MLP expansion ratio |
| `--force-prepare` | off | Rebuild processed data before the run; also regenerates its amputation artifact |
| `--force-amputation` | off | Regenerate the artificial missingness artifact before the run |

The run command automatically prepares the dataset if processed files do not exist. Existing processed and amputation artifacts are reused by default. Use `--force-prepare` when preprocessing must be rebuilt, for example after changing preprocessing code or dependencies. Use `--force-amputation` to regenerate the missingness mask for the same configuration and seed.

For a quick integration/smoke test, use a small epoch count and model dimensions, for example:

```powershell
python run_experiment.py run `
  --dataset wine_red `
  --mechanism MCAR `
  --epochs 2 `
  --batch-size 128 `
  --embed-dim 16 `
  --depth 1 `
  --decoder-depth 1 `
  --device cpu `
  --models pmae,remasker
```

A smoke test confirms that the software path executes; it is **not** a meaningful benchmark and should not be reported as a research result.

## Experiment outputs

Each experiment writes to a configuration-specific directory:

```text
results/<dataset>/<mechanism>/
└── columns_<fraction>/rate_<missing-rate>/seed_<seed>/
    ├── metrics.json
    ├── experiment_config.json
    ├── pmae_imputed.csv
    ├── pmae_imputed_encoded.csv
    ├── pmae_training_history.json
    ├── pmae_model_checkpoint.pt
    ├── remasker_imputed.csv
    ├── remasker_imputed_encoded.csv
    ├── remasker_training_history.json
    └── remasker_model_checkpoint.pt
```

Files for a model that was not selected are not produced. The decoded CSVs restore categorical labels; the encoded CSVs retain numeric ordinal codes for downstream processing. Checkpoints contain the model weights, normalization information, feature order, categorical mappings, and training configuration. The JSON files record the configuration and measured metrics needed to interpret a run.

Generated processed data, amputated data, checkpoints, results, and logs are excluded from Git by the repository's `.gitignore`. Raw datasets are intentionally included in the repository structure.

## Evaluation metrics

Evaluation is performed only on the cells hidden by the artificial missingness mask. The current evaluator reports:

- **Normalized MAE:** mean absolute error after scaling numerical-coded feature values to their ground-truth feature ranges.
- **Normalized RMSE:** root mean squared error on the same normalized values.
- **Numerical MAE / RMSE:** normalized errors on numerical features only.
- **Numerical R²:** mean missing-only R² across numerical features where the metric is defined.
- **Categorical accuracy:** exact-match accuracy after rounding and clipping predicted ordinal category codes to valid category indices.
- **Categorical-code MAE:** absolute error between predicted and true ordinal codes; interpret cautiously because category codes do not have an intrinsic metric ordering.
- **Wasserstein distance:** feature-wise distribution distance on normalized values, including the aggregate normalized distance.

The evaluator also records the sample count, feature count, artificial missing-cell count, and realized missing fraction. Because mixed-type aggregate metrics currently operate on ordinal-coded categorical values, they should be interpreted alongside the separate numerical and categorical metrics and the categorical-model limitation described above.

## Known limitations and future work

- **Categorical modeling:** replace scalar ordinal-code reconstruction with categorical embeddings, a categorical output head, and a categorical-appropriate loss.
- **Experimental coverage:** complete the planned dataset/mechanism/rate/seed combinations and report aggregate results across multiple random seeds.
- **Baselines:** add additional established imputation baselines under the same preprocessing and missingness protocol where appropriate.
- **Reproducibility:** record exact package versions, hardware, random seeds, and full configurations for all reported experiments.
- **Dataset governance:** verify the redistribution terms and attribution requirements for every bundled dataset before public redistribution.
